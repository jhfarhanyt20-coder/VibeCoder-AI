# Docs writer

Use this to write or update a README or user guide from the real code.

1. **Read before writing.** Find what the project really does, how it is installed, run, configured and tested. Run the commands you document so they are correct.
2. **Write for a new user,** in this order: what it is (2 sentences), a screenshot or example if there is a UI, install, run, configure (every setting with its default; never real secret values), test, build or release, troubleshooting for the errors people really hit.
3. **Keep it short and exact:** copy-paste commands in code blocks, real file names, no marketing words.
4. **Update, do not duplicate:** if a README exists, keep its good parts and fix what is wrong or missing.
5. Show the user the finished document and the list of commands you verified.
